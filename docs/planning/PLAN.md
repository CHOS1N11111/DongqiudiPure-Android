# 实施计划

> 本文只维护实施顺序、状态、依赖和退出条件。阶段边界见 [PRODUCT.md](../product/PRODUCT.md)，逐项能力见 [FEATURES.md](../product/FEATURES.md)，技术边界见 [ARCHITECTURE.md](../engineering/ARCHITECTURE.md)。

## 1. 当前状态

- 项目阶段：M3 资讯与公开内容进行中。
- Android 工程：M1 scaffold 已完成；真实匿名资讯流、文章详情和一级评论已接入。
- 已有资产：四项根导航、Hilt/Paging 数据基础、脱敏 contract fixture、CI 和 `GPL-3.0-only` License。
- M2 的通用 contract 基础与首组资讯 contract 已完成，其他公开能力盘点继续随对应 milestone 归档。
- 固定顺序：匿名核心版（M2-M8）-> 登录与主队（M9-M10）-> 完整匿名公开数据（M11-M12）-> 账号能力（M13-M15）-> 本机增强与发布准备（M16-M17）。
- 登录成功样本和专用测试账号在 M9 前准备，不阻塞第一阶段。

状态使用：`未开始`、`进行中`、`已完成`、`被阻塞`、`暂缓`。

## 6. M2：公开能力盘点与 contract 基线

### 公开入口盘点

- 以当前官方客户端和官网的未登录状态为样本，逐层记录根入口、二级入口、详情 section、筛选项和可达实体。
- 将每个公开能力映射到 [FEATURES.md](../product/FEATURES.md)；新发现项先入矩阵，不直接塞入某个页面实现。
- 为每项能力记录匿名可用性、数据来源、候选 endpoint 和证据等级；无法验证时保持“待验证”。
- 不使用付费内容、登录私有数据、第三方拼接结果或安全机制绕过补齐公开范围。

### Contract 基础设施

- 实现只负责 HTTP 的 transport，不向上层暴露 OkHttp Response 类型。
- 建立 Request profile：Host allowlist、User-Agent、UUID、超时、取消和有限重试。
- 建立 DTO -> Domain mapper，并明确处理缺失字段、额外字段和类型变化。
- 建立 `ApiError` 分类：Network、HTTP、Server、Parse、Auth、RateLimited、UnsupportedContract。
- 用 MockWebServer 保存脱敏的 success、empty、server error 和 malformed fixture。
- 隔离 anonymous read、authenticated read 与 write client；后两者此阶段不连接功能 UI。
- 将 endpoint 证据和 contract 更新到 [API.md](../protocol/API.md)。

### 退出条件

- 当前样本中发现的公开入口均已进入功能矩阵，并分配到 M3-M8、M11-M12 或明确排除。
- 至少一个匿名 endpoint 同时通过 fixture test 与低频 live read smoke test。
- parser 容忍新增非关键字段，关键字段缺失时返回可诊断错误。
- 日志与 fixture 不包含凭据、账号标识或完整敏感 query。

## 7. M3：资讯与公开内容

### 任务

- 完成 [FEATURES.md](../product/FEATURES.md) 中分配给 M3 的 contract，再实现对应页面。
- 资讯流支持初次加载、刷新、分页、去重、分类切换和滚动位置恢复。
- 文章支持正文、图片、公开关联实体、受控外链和系统分享。
- 公开评论支持排序、分页、回复关系和用户摘要；评论失败不影响正文。
- 专题、话题、图集和视频只有通过 contract gate 的部分进入正式 UI，其他项保留明确状态。
- 各数据块分别建模 loading/content/empty/error，避免整页共享一个失败状态。

### 退出条件

- M3 功能项均达到“已实现”“被阻塞”或“明确排除”，状态同步回功能矩阵。
- 匿名资讯连续浏览、分页恢复和关联跳转通过验收。
- 核心 parser、Repository、ViewModel 和页面状态具备与风险相称的自动化验证。

## 8. M4：比赛中心基础

### 任务

- 支持日期切换，并提供从赛事或球队进入赛程/赛果的稳定查询模型。
- 统一表示未开始、进行中、完场、延期、取消、腰斩、点球和未知状态。
- 建立比赛详情壳层，展示时间、轮次、场地、裁判、主客队及已验证赛前信息。
- 比分更新可取消、感知前后台且有刷新上限；终场后停止实时策略。
- 建立时区、跨日、夏令时、状态变化和列表稳定性验证。

### 退出条件

- 用户可以未登录完成“日期或赛事 -> 比赛列表 -> 基础详情”。
- 比分变化不导致列表跳动或丢失滚动位置。
- 未知状态和缺失字段不会崩溃，也不被误显示为完场或零值。

## 9. M5：完整比赛数据

### 任务

- 为事件、阵容、技术统计、赛前信息和赛后信息分别固化 endpoint 与 fixture。
- 事件模型覆盖进球、助攻、红黄牌、换人、VAR、点球大战，并保留未知事件类型。
- 阵容模型覆盖首发、替补、教练、阵型、位置、号码和公开缺阵信息。
- 技术统计使用服务端驱动的指标模型，不能只支持预先写死的一小组统计项。
- 每个详情 section 独立加载、刷新、缓存和失败；单项 contract 变化不清空其他 section。
- 实时比赛采用合并更新，避免事件重复、倒序或比分与时间线不一致。

### 退出条件

- [FEATURES.md](../product/FEATURES.md) 中 M5 的每项能力均有明确结论。
- 具备数据的比赛可完整浏览事件、阵容和技术统计；不存在的数据明确显示缺失而不是伪造空内容。
- 赛前、进行中、完场和异常中止样本均通过 fixture 与状态转换验证。

## 10. M6：主要/热门榜单

### 任务

- 根据 M2 归档的官方匿名默认/热门入口固定本期赛事集合、来源和基线日期。
- 为该集合接入当前赛季积分榜、射手榜和赛程赛果，并验证助攻及核心球队/球员统计榜。
- 建立可扩展的 CompetitionId、SeasonId、StageId、GroupId 和 RoundId 模型，为 M11 留出长尾扩展能力。
- 处理核心样本中的小组赛、多阶段赛制、并列排名、扣分和无榜单状态。
- 榜单行通过稳定 ID 进入球队、球员、比赛或赛事资料页。

### 退出条件

- [FEATURES.md](../product/FEATURES.md) 中 M6 的主要/热门范围进入终态。
- M2 归档的热门赛事可浏览当前赛季核心榜单，范围外赛事明确留给 M11。
- 排名、数据缺失和“不适用”具有不同语义。

## 11. M7：主要/热门资料库

### 任务

- 为 TeamId、PlayerId、CompetitionId 和 SeasonId 建立通用 Domain 类型与路由 contract。
- 使用主要赛事和热门实体样本实现球队主页/阵容、球员主页/当前数据、赛事主页/当前赛季。
- 接入热门球队资讯、比赛、排名和已验证统计；实体 section 独立加载与降级。
- 模型和 Repository 不得按热门名单分支，确保 M10 可以按任意主队 ID 发起同类公开读取。
- feature 之间只传稳定 ID，资料由 Repository 加载。

### 退出条件

- M7 归档范围内的球队、球员和赛事可从公开入口进入并互相关联。
- 通用页面能够接收范围外实体 ID；未知或未覆盖 section 明确降级，不显示“不支持该球队”。
- 历史履历、长尾实体和完整覆盖明确留给 M12。

## 12. M8：核心搜索、关联与匿名核心收口

### 任务

- 接入搜索和分类结果，覆盖资讯及 M6/M7 已支持的球员、球队和赛事。
- 统一实体链接解析和 deep link；未知类型安全降级，不把任意 URL 交给带账号 Header 的 client。
- 走查 M3-M8 的匿名核心入口，将新增、改名或消失项更新到功能矩阵和 API 证据表。
- 对被阻塞项记录证据路径、用户影响和复审条件。
- 执行匿名核心回归：资讯、完整比赛、热门榜单、热门资料、搜索和跨实体导航。

### 匿名核心 Gate

- [FEATURES.md](../product/FEATURES.md) 第 2 节不存在“待盘点”“待验证”“Contract 待归档”或“实现中”。
- M3-M8 的所有能力均不依赖登录或 Authorization。
- [PRODUCT.md](../product/PRODUCT.md) 的第一阶段验收全部通过。
- 第 4 节的完整公开范围可以保持待办，不阻塞 M9。

只有关闭该 Gate 后才开始 M9。

## 13. M9：登录与会话

### 前置 Gate

- 已有用户明确授权的专用懂球帝测试账号。
- 只允许登录和只读验证；不执行发帖、回复、点赞、关注、收藏、删除或资料修改。

### 任务

- 用成功样本确认密码表示方式、Authorization 所在字段和 challenge 分支。
- 实现密码登录、会话验证、加密持久化、冷启动恢复、失效和退出。
- 统一会话状态，页面不得自行判断 Header 或 HTTP code。
- 分别处理账号错误、版本过低、限流、网络失败和未知 challenge。
- session import 只作为内部诊断候选，是否进入正式 UI 另行决策。
- 审查日志、截图和 fixture，确认没有 Secret 或可恢复账号身份的数据。

### 退出条件

- 专用账号完成登录 -> `/v2/user/is_login` -> 重启恢复 -> 退出流程。
- 密码未落盘，Authorization 仅存在于加密存储与必要的内存会话中。
- 登录失败和会话过期均可无损回到匿名模式。

## 14. M10：账号主队入口

### 任务

- 只读取识别当前账号和主队所需的最少字段。
- 通过真实成功 contract 确认主队字段、球队 ID、未设置和字段缺失的表示方式。
- 根据主队 ID 使用 M7 的通用球队 Repository；主队不在热门集合时仍尝试加载可用公开 section，不复制登录专用数据链路。
- 账号没有主队时显示未配置状态，不调用未验证的资料修改接口代替用户设置。
- 账号数据与匿名 cache 分区；退出清除 Secret 和账号私有数据，不删除公开 cache。

### 退出条件

- 主队存在、未配置、字段缺失和账号接口失败均有稳定状态。
- 主队入口只负责个性化定位；所有成功加载的球队公开内容在退出登录后仍可访问。

## 15. M11：完整榜单与数据扩展

### 任务

- 将 M6 的赛事集合扩展到所有存在官方匿名入口且 contract 可验证的赛事、赛季、阶段和分组。
- 补齐长尾与历史积分榜、射手榜、助攻榜、赛程赛果及球队/球员统计榜。
- 覆盖杯赛、资格赛、附加赛、多阶段联赛、跨年赛季和历史规则差异。
- 复用 M6 的 Domain 与 UI；新增格式通过兼容模型扩展，不复制一套“完整榜单”页面。
- 所有扩展 Request 继续使用 anonymous read client，不携带 Authorization。

### 退出条件

- [FEATURES.md](../product/FEATURES.md) 的 M11 条目全部进入终态。
- 已发现的公开赛事/赛季榜单均可浏览，或记录具体阻塞与复审条件。
- 登录、退出和会话失效不改变榜单可用范围。

## 16. M12：完整公开资料库与范围收口

### 任务

- 将 M7 扩展到所有 contract 可验证的球队、球员、赛事、赛季和其他公开实体。
- 补齐长尾与历史资料、阵容、工作人员、履历、转会、比赛、数据和关联内容。
- 盘点无需登录可见的公开用户页、帖子、动态和社区聚合，并逐项处理。
- 将搜索、关联导航和 deep link 扩展到全部已支持公开实体。
- 重新走查当前官方匿名入口，将每项能力标记为已实现、被阻塞或明确排除。
- 被阻塞项记录证据路径、用户影响、可接受替代和复审触发条件。

### 完整公开数据 Gate

- [FEATURES.md](../product/FEATURES.md) 第 4 节不存在“待盘点”“待验证”“Contract 待归档”或“实现中”。
- M11/M12 的页面、Request 和 cache 不依赖账号或 Authorization。
- [PRODUCT.md](../product/PRODUCT.md) 的第三阶段验收全部通过。
- 长尾实体、历史数据和完整搜索完成统一回归。

## 17. M13：账号只读页面

### 任务

- 按 [FEATURES.md](../product/FEATURES.md) 的 M13 项逐个验证账号资料、消息、关注动态、收藏、关注/粉丝和账号内容记录。
- 每项能力拥有独立 endpoint contract、分页状态和权限失败处理。
- 明确消息列表读取与“标记已读”等远端写操作的边界；M13 不隐式发送任何写 Request。
- 私有响应不写入共享公开 cache，脱敏 fixture 不能保留消息正文、账号 ID 或联系人标识。
- 会话失效时停止私有数据加载并清理页面状态，不影响匿名页面。

### 退出条件

- M13 中可验证的只读账号页完成，未验证能力不可达。
- 退出账号后无法从历史页面、内存状态或磁盘 cache 恢复私有数据。

## 18. M14：可逆远端互动

该 milestone 默认暂缓。点赞、关注、收藏以及消息已读等动作虽然通常可逆，仍会改变远端状态。

- 每个 capability 单独确认 method、path、body、幂等性、风控响应和成功语义。
- 每个 capability 使用独立 Repository command、UI 状态和 feature flag。
- write client 默认不自动重试；超时后显示“结果未知”，通过后续只读查询确认状态。
- 先用 MockWebServer 完成提交中、明确成功、明确失败、timeout、重复点击和撤销流程。
- 未获得隔离测试环境和明确授权前，不对真实账号发送实验性写 Request。

退出条件是每项能力可以独立关闭、Mock 和恢复流程完整，且没有把本地乐观状态当成服务端成功证明。

## 19. M15：发布、资料与破坏性操作

- 发表评论/回复、发帖、发送私信、删除/编辑内容和修改资料逐项建立独立 contract。
- composer 先支持本地 draft 和 Mock submit，再连接通过 Gate 的真实 capability。
- 发布内容明确展示目标、账号和最终提交动作，防止重复提交或发错上下文。
- 删除、资料修改和主队修改在提交前展示准确影响；结果未知时不得自动重试。
- 媒体上传单独验证格式、大小、上传状态、残留文件和失败清理。
- 没有隔离测试环境、明确授权和可恢复方案的能力保持关闭。

退出条件是每项已开放能力都能独立禁用，具备明确成功/失败/未知结果处理，并完成账号风险审查。

## 20. M16：本机增强

- 阅读历史、稍后读、离线、屏蔽和备份按真实使用需求逐项排期。
- 只有出现持久关系查询需求时引入 Room，不为未来候选预建复杂 schema。
- 离线内容记录来源时间并允许清理；账号私有数据不进入普通备份。
- 本机功能不改变公开数据 contract，也不阻塞匿名浏览能力。

## 23. 全局 Definition of Done

一个任务只有同时满足以下条件才算完成：

- 行为与 `PRODUCT.md` 的阶段边界一致，功能状态已在 `FEATURES.md` 更新。
- API 变化已更新 contract fixture 和 `API.md` 的证据状态。
- 正常、空数据、错误、无网络、取消和恢复路径均被考虑。
- 自动化验证覆盖本次新增的关键 parser、状态转换或 UI 行为。
- 日志、fixture 和缓存通过敏感信息检查。
- 在最低支持和当前 Android 环境完成与风险相称的验证。
- 文档只在其权威文件完整描述，没有复制一份会独立过期的功能清单。
