# 产品范围

> 本文是产品目标、阶段边界与阶段验收的单一信息源。逐项能力见 [FEATURES.md](FEATURES.md)，实施顺序见 [PLAN.md](../planning/PLAN.md)。

## 1. 产品定位

`DongqiudiPure-Android` 是面向 Android 的轻量非官方懂球帝客户端。项目优先提供可连续浏览、可关联检索的公开足球信息；登录不是任何公开内容的访问前置条件。

产品按以下顺序推进：

1. 完成匿名资讯、完整比赛数据、主要/热门榜单及主要/热门球员、球队、赛事资料。
2. 实现登录和会话管理，并依据账号主队信息进入对应球队内容。
3. 继续补齐长尾赛事、历史赛季、完整榜单和完整公开资料库；此阶段虽然排在登录后，功能仍支持未登录访问。
4. 实现账号只读页面，再按风险逐项开放会改变远端状态的操作。

项目明确排除广告、博彩/体育投注及相关导流、运营商业系统和安全机制规避；具体边界见 [FEATURES.md](FEATURES.md)。

## 2. 核心原则

1. **公开数据不依赖登录**：所有公开页面使用匿名数据链路；实现顺序不能改变访问权限。
2. **先核心、后完整**：登录前先形成覆盖主要/热门内容的可用产品，登录后再继续补齐长尾公开数据。
3. **范围可核对**：官方公开入口中的能力必须进入 [FEATURES.md](FEATURES.md)，状态不能只存在于口头约定或代码中。
4. **完整但不伪造**：服务端缺失的数据如实降级，不以零值或占位内容冒充完整数据。
5. **关联可达**：资讯、比赛、榜单、球员、球队和赛事通过稳定 ID 互相跳转。
6. **失败隔离**：单个 endpoint、页面 section、登录或实验功能失效时，不破坏无关页面。
7. **账号能力分级**：账号只读数据与远端状态变更使用不同的权限、网络和验收边界。
8. **最少数据**：不为统计或推荐额外采集用户数据；密码不持久化，凭据不进入日志和 fixture。

## 3. 第一阶段：匿名核心版

第一阶段在登录开发前完成，范围包括：

1. **资讯与公开内容**：首页、分类、文章、公开评论，以及 contract 可验证的专题、话题、图集和视频。
2. **完整比赛数据**：赛程、赛果、实时状态、完整事件、阵容、技术统计、赛前信息和赛后信息。
3. **主要/热门榜单**：主要赛事和官方热门入口中的积分榜、射手榜、赛程赛果及可验证的其他统计榜。
4. **主要/热门资料**：主要赛事和热门球员、球队的当前资料、阵容、赛程、数据与关联资讯。
5. **核心搜索与关联**：能够搜索和连接第一阶段已经支持的资讯、比赛、榜单与实体。
6. **匿名主队中心**：用户可从真实搜索结果在本机选择主队、关注球队或球员，并进入其公开动态、赛程、数据、阵容、圈子和资料；没有数据时如实降级。

“主要/热门”的具体集合在 M2 根据官方匿名默认入口和热门分类归档到 [FEATURES.md](FEATURES.md)，不能在页面中写死为永久名单。

### 第一阶段验收

- 未登录可以完成“资讯流 -> 文章 -> 公开评论 -> 关联实体”的连续浏览。
- 未登录可以完成“日期/赛事 -> 比赛 -> 事件/阵容/技术统计 -> 关联实体”的完整比赛路径。
- 未登录可以浏览已归档主要/热门范围内的榜单、球员、球队和赛事资料。
- 比赛详情和资料页的各 section 独立加载、独立失败；部分 contract 变化时其余内容仍可使用。
- 网络断开、空数据、分页结束、Response 不兼容和服务端错误均有明确状态。
- [FEATURES.md](FEATURES.md) 第一阶段条目均已实现，或以证据充分的“被阻塞/明确排除”结案。

## 4. 第二阶段：登录与主队

第二阶段不改变匿名根路径，也不把第一阶段公开 Request 改成 authenticated Request。

- 支持用户名或手机号加密码登录，并覆盖版本过低、凭据错误、限流和未知 challenge。
- 新会话经过服务端状态验证后才能持久化；重启恢复、失效和退出由统一会话状态管理。
- 登录后只读取识别账号和主队所需的最少字段，根据主队 ID 进入公开的球队资料、资讯、比赛和数据。
- 主队不在 M7 的热门样本中时，仍使用通用球队 ID 和 Repository 加载；长尾 section 可以降级，但不能拒绝进入。
- 未设置主队、字段缺失或账号接口失败时正常降级。
- 匿名选择继续保存在本机；只有取得已验证的账号 contract 后才增加跨设备同步，不能把本机选择冒充为服务端关注成功。

### 第二阶段验收

- 完成登录、会话验证、加密存储、冷启动恢复、失效和退出的端到端只读验证。
- 登录失败或会话过期后，应用无损回到匿名模式。
- 主队存在、非热门、未设置和字段不兼容均有明确状态，且主队入口不复制登录专用的公开数据实现。

## 5. 第三阶段：完整匿名公开数据

第三阶段排在登录与主队之后，但仍使用 anonymous read client，并允许用户退出登录后完整浏览。

- 将榜单从主要/热门赛事扩展到所有 contract 可验证的公开赛事、赛季、阶段和历史数据。
- 将资料库扩展到所有可验证的球员、球队、赛事、赛季及其他公开实体。
- 补齐长尾实体的阵容、履历、转会、赛程、赛果、统计、关联资讯和跨实体导航。
- 重新审计官方匿名入口，对所有能力给出已实现、被阻塞或明确排除结论。

### 第三阶段验收

- 完整公开数据不发送 Authorization，也不因用户退出而减少功能。
- [FEATURES.md](FEATURES.md) 中完整公开范围不存在待盘点、待验证、Contract 待归档或实现中状态。
- 长尾赛事、历史赛季和非热门实体遵守与核心范围相同的错误与降级标准。

## 6. 第四阶段：账号能力

第四阶段按实际风险拆分，而不把所有登录后页面视为同一种操作。

### 6.1 账号只读

消息、关注动态、收藏列表、关注/粉丝列表、账号内容记录等能力需要凭据并涉及私有数据，但只读 Request 不改变远端状态。它们在退出时清理账号私有缓存。

### 6.2 远端状态变更

点赞、关注、收藏、消息状态、发表评论/回复、发帖、发送私信、删除内容和修改资料都会改变服务端状态。每项能力必须拥有独立 contract、独立开关和明确结果语义；非幂等 Request 默认不自动重试。

开发和验证阶段不使用真实常用账号做实验性写入。没有隔离测试环境、授权样本或可验证 contract 时，只保留 Mock 流程。

## 7. 导航

根 Navigation 保持 `资讯 / 比赛 / 主队 / 数据 / 我的`（D-016 第四次修订）：

- `资讯` 承载公开内容入口，并通过搜索与关联链接进入资料库。
- `比赛` 是日期视角：按日期浏览赛程赛果与完整比赛详情。
- `主队` 是本机个性化入口：中间展示主队队徽，可切换主队、关注球队和球员；公开内容不依赖登录。
- `数据` 是赛事视角：赛事切换器加当前赛事的积分榜、射手榜、助攻榜与赛程。
- `我的` 在未登录时提供登录入口与本机设置，登录后提供账号能力。

`比赛` 与 `数据` 的切分维度不同（日期 vs 赛事），不是同一批内容的两个入口。

搜索和实体详情是内容目的地或二级入口，不增加固定根 tab。球员、球队与赛事资料通过搜索、榜单行和比赛阵容进入 —— 它们没有可合法枚举的目录页（无服务端目录接口，按热门写死违反 FEATURES.md 的不写死永久名单）。

## 8. 非功能要求

- **兼容性**：最低支持 API 26；`compileSdk` 和 `targetSdk` 使用 scaffold 时受支持的稳定版本。
- **可访问性**：主要交互具备语义标签，支持系统字体缩放，颜色不是唯一状态提示。
- **自适应**：手机、折叠屏和平板使用稳定的 compact/medium/expanded 布局策略。
- **可维护性**：API path、Header、DTO 和兼容 profile 集中管理；页面不直接拼装 Request。
- **可诊断性**：错误可分类但不泄露凭据；Debug 信息只保留脱敏的 endpoint、HTTP 状态和 parser 阶段。
- **权限与隐私**：匿名阶段只申请网络所需权限，不接入第三方 analytics；账号数据与公开缓存分区。
- **性能**：首个 vertical slice 后建立真实基准，再确定启动、列表、图片和内存目标。

## 9. 发布边界

- 对外发布前补齐应用名称、原创图标、包名、License、隐私说明和第三方依赖声明。
- README、应用内“关于”和发布页保留非官方声明。
- 不保证非官方 API 永久可用；通过独立降级、关闭单项能力和版本更新处理兼容问题。
- 不主动发布 Release，发布动作必须由用户明确提出。
