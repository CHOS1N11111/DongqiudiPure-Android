# 功能覆盖矩阵

> 本文是逐项功能范围与覆盖状态的单一信息源。阶段边界见 [PRODUCT.md](PRODUCT.md)，实施顺序见 [PLAN.md](../planning/PLAN.md)，接口证据见 [API.md](../protocol/API.md)。

## 1. 覆盖口径

公开数据分两批交付：

- **主要/热门范围**：当前官方客户端或官网在未登录状态下默认展示、标记为热门或作为主要入口提供的赛事和实体。M2 必须记录具体名单、来源入口和基线日期，M6/M7 不在代码中写死永久名单。
- **完整公开范围**：所有无需账号、存在官方公开入口且 contract 可通过合规低频 Request 验证的资讯、比赛、榜单和资料。M11/M12 排在登录后实施，但仍属于匿名功能。

两批范围都不包含广告、博彩/体育投注内容、运营活动或官方页面布局复刻。每个能力使用以下状态：

| 状态 | 含义 |
| --- | --- |
| 待盘点 | 已知存在某个领域，但尚未完成官方公开入口清单 |
| 待验证 | 已列入范围，但匿名可用性或 Request contract 尚无直接证据 |
| 可匿名，Contract 待归档 | 已确认无需登录可读取，但 path、schema 和脱敏 fixture 尚未完整归档 |
| Contract 已验证 | 已有可复现 Request、脱敏 fixture 和 parser 边界 |
| 实现中 | 已通过 contract gate，正在实现客户端能力 |
| 已实现 | 功能、降级和验收路径均完成 |
| 被阻塞 | 已记录具体外部阻塞、证据和复审条件 |
| 明确排除 | 不属于产品范围，并记录排除原因 |

## 6. 明确排除

| 能力 | 状态 | 原因 |
| --- | --- | --- |
| 广告、商业推广与赞助导流 | 明确排除 | 不展示开屏、信息流、横幅、贴片、弹窗或导购广告，也不建立广告画像 |
| 博彩与体育投注相关内容 | 明确排除 | 不展示赔率、盘口、竞彩、投注技巧、投注推荐、投注平台或相关导流 |
| 博彩性质的预测与竞猜 | 明确排除 | 不实现以投注、奖金或博彩推广为目的的预测、竞猜和账户能力 |
| 运营弹窗和活动页复刻 | 明确排除 | 不属于资讯与资料能力 |
| 付费或 DRM 直播源 | 明确排除 | 不绕过授权和内容保护 |
| 地区限制、CAPTCHA、设备证明或安全机制绕过 | 明确排除 | 不以规避平台安全措施换取功能 |
| 拼接非官方第三方抓取结果 | 明确排除 | 不能作为懂球帝公开资料 contract 的替代品 |

## 7. 完成判定

- 单项功能只有达到“已实现”才算客户端已覆盖；“可匿名”或“Contract 已验证”不等于实现完成。
- 匿名核心版完成时，第 2 节条目必须是“已实现”“被阻塞”或“明确排除”，不要求第 4 节同时完成。
- 完整公开数据完成时，第 4 节不存在“待盘点”“待验证”“Contract 待归档”或“实现中”。
- 第 4 节排在登录后只代表开发顺序；其 Request、缓存和页面不得依赖账号或 Authorization。
- API 返回部分数据时如实显示并标记缺失，不能把缺失字段伪造成零、空阵容或完整履历。
- 具体 endpoint 的证据等级只在 [API.md](../protocol/API.md) 维护，本矩阵只记录能力层状态。
